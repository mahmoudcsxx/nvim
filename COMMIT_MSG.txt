Fix two broken config files; correct and complete the README

Fixes
- snippets/java.lua used `then` as a table key. `then` is a Lua reserved word, so
  the file was a syntax error and had never loaded - all 15 Java snippets were
  silently unavailable. Quoted the key: ["then"]. The file is loaded at runtime
  by luasnip.loaders.from_lua, so this was user-visible.
- lua/config/keymaps.lua mapped <leader>xq to <cmd>TroubleToggle quickfix<cr>,
  which is the trouble.nvim v2 command. The rest of the config already uses the
  v3 API (require("trouble").is_open(), <cmd>Trouble diagnostics toggle<cr>), so
  that mapping was dead. Now <cmd>Trouble quickfix toggle<cr>.

README
- The Structure tree omitted lua/plugins/discord.lua. It now matches the files
  on disk exactly.
- Install instructions assumed ~/.config/nvim. Neovim reads its config from
  %LOCALAPPDATA%\nvim on Windows, so Windows and Linux/macOS are now documented
  separately.
- Added the Discord Rich Presence plugin to Highlights, and the <leader>wd,
  <leader>fn, <A-j>/<A-k> and <leader>xq> mappings to the keymap table.
- Noted that the published config can lag behind the local one.

Verified with nvim 0.12.5, headless, against a copy (the live config at

- Parsed all 22 Lua files with loadfile(): 22 pass, 0 fail (was 21/1).
